# Changelog

## Unreleased

- **Cues: sound and haptics on the motion's own clock (format 1.3).**
  - A file names moments: `"cue": { "haptic": "success", "sound": "pop" }`, on a transition, on entering a state, or on a beat of entry keyframes or a loop.
  - A cue can carry intensity, pitch (in semitones), a delay (including one read from an input, so a stagger ticks with its items), a repeat and a throttle. Intensity and pitch can read an input.
  - The runtime reports cues at exact times through `takeCues()`. Cues on a state stop when it is left. Under reduced motion their delays go, and skipped beats leave one cue at the moment.
  - Every adapter plays them:
    - web: Web Haptics where a browser has it, otherwise `vibrate` on Android browsers, and sounds from a `sounds` map;
    - iOS: UIKit's feedback generators, and AVAudioPlayer for `model.sounds`;
    - Android: `performHapticFeedback`;
    - React Native: a `haptics` function you pass, such as `expoHaptics(Haptics)`.

    `onCue` hands each cue to the host for custom names and audio engines.
  - TypeScript, Swift and Kotlin share four new conformance cases: `cues`, `cue-beats`, `cue-beats-reduced` and `cue-throttle-delay`.
  - A compiled program that uses cues is format 10.
  - New validator codes: `unknown-haptic` and `invalid-cue`.
  - `nudg audit` flags sounds and haptics played by hand.
- **Format 1.3: shadow, blur, and custom properties.**
  - `shadowX`, `shadowY`, `shadowBlur` and `shadowColor` are plain properties with their own motion, so a lifted card's shadow deepens with the same spring that raises it. `blur` blurs a view.
  - Adapters draw them as `box-shadow` and `filter` on the web, `.shadow` and `.blur` in SwiftUI, and `Modifier.dropShadow` and `Modifier.blur` in Compose. On React Native, `shadowRadius`, `shadowColor` and `elevation` are drawn; shadow offsets and blur, which React Native can't animate, are skipped with a warning.
  - For what no nudg property draws, `target.custom.<name>` is a number nudg moves and the host draws. It is declared under `host.custom`, and on the web it is also the CSS variable `--nudg-<name>`. React Native has `value("card.custom.glow")`.
  - Guardrails: a custom name that nudg draws already (`shadow`, `filter`, `opacity`) is an error naming the built-in, and `nudg audit` lists the custom properties an app uses.
  - TypeScript, Swift and Kotlin share the new conformance cases `shadow-blur-custom` and `validation-1.3`.
  - Schema 1.3. New validator codes: `undeclared-custom` and `custom-is-built-in`.
- **CSS no longer fights a file's motion.** A page's CSS transition or keyframe animation on a property a nudg file writes eased or overwrote every frame. PlaySnack's buttons had `transition: transform .06s` under the nudg press, so the spring arrived late. The DOM adapter now turns those off on the bound element, keeps the rest (a color transition, `transition: all` minus what nudg moves), restores them when the player lets go, and warns once per class so the stylesheet can be cleaned up.

## 1.8.0

How much of an app is on nudg, as a number, and less code to get it to 100%. `nudg audit` finds motion outside nudg and names what replaces each piece. PlaySnack measures 49%, and 38 of its 40 findings can be replaced today. `leaving` and `playEach` replace the last two pieces of glue PlaySnack wrote: the sheet closer and the document-wide press listener. The format stays 1.2; the API only gains.

- **`nudg audit`: is an app's motion on nudg?** `nudg audit src` (MCP `nudg_audit`) finds motion that lives outside nudg:
  - CSS keyframes, and transitions of moving properties;
  - Web Animations and other motion libraries;
  - transforms written by hand;
  - frame loops;
  - timers and listeners around players.

  Each finding names what in nudg replaces it. It starts with the share of motion on nudg, and marks gaps nudg can't cover yet (a keyframe animation of `box-shadow`) to report instead of working around. The skill has agents run it after wiring nudg in. Our examples: 100% for the messenger, one CSS fade left in the video player. PlaySnack: 49%, with 38 of 40 findings replaceable today.
- **`playEach`: one file on every element that matches.** `playEach(presets.press(), "button")` gives every button the same press. An element gets its player when a finger lands, in time for that touch, or as it appears (`when: "mount"`). Removed elements are let go, and disabled controls and `[data-nudg-off]` are skipped. A function of the element picks a variant. PlaySnack kept an 81-line document listener for this.
- **`leaving`: the way out, as a flag.** Every adapter has it next to `present` (`player.leaving()`, `leaving` in the React and React Native hooks, `model.leaving` in SwiftUI, `state.leaving` in Compose), from the runtimes' shared lifecycle. It is true from the moment the machine enters an exit state from elsewhere until `onExit`, so a dim behind a leaving sheet lets taps through without the host tracking it. PlaySnack kept a 78-line closer for this; everything else in it was already `exit`, `onExit` and `present`.

## 1.7.0

Less code around nudg. PlaySnack drives every interaction with nudg, but kept 731 lines of its own motion code and CSS keyframes on seven screens. Part of that was missing from nudg; part of it was already there, and the agent never found it. This release fixes both: one-shots let go by themselves, entrances are one hook, a hidden tab still ends its motion, and the guide and skill now cover the app side. The format stays 1.2; the API only gains.

- **One-shots without glue.** `playDoc(file, el, { start, release })` sends `start` as soon as the elements are bound and lets go by itself at the first rest (or at the exit): the player is destroyed and the elements get their own styles back. `player.done` resolves then. React's `useNudgOnce(file, { replay })` plays a way in on mount and again when `replay` changes. New presets: `pop`, `drop` and `shake`. A trophy that drops in, a countdown number that pops and a field that shakes are each one line, with reduced motion and the tools included, where PlaySnack had CSS keyframes and its own release helper.
- **Agents wire nudg without glue.** PlaySnack's agent-written motion code kept timers, wrappers and CSS keyframes for things the adapters already did (unmounting after the way out, knowing when motion is over, nudgTransition), because the guide and skill taught the file and not the host side. The guide has a new section, "Wire it without glue", mapping what an app needs to the adapter call that does it; the skill and the MCP instructions point to it.
- **A hidden tab still reaches the end.** The DOM adapter moved only on animation frames, which a background tab never draws, so `onSettle` and `onExit` never came there: a sheet closed in another tab never unmounted, and hosts kept fallback timers for it. Each frame is now backed by a timer, so the motion lands at its end and the callbacks come. Found in PlaySnack's motion code ([devlog](docs/devlog.md#2026-11-10-what-playsnack-wrote-around-nudg)).

## 1.6.0

What a whole app needed. PlaySnack applied nudg across its screens and filed seven issues in a day; all seven are fixed here. Players on one element now compose, a staggered list keeps its rhythm in the file with format 1.2's delay from an input, and reduced motion follows the system as it changes, on every platform. Format 1.2 only adds; 1.1 files and compiled programs that don't use the new delay read as before.

- **Format 1.2: a delay read from an input.** A list whose items rise one after another keeps its rhythm in the file and its order in the app: `"delay": { "input": "host.index", "times": 0.06, "max": 0.5 }`, with each item's player given `host.index`. The delay is `input × times + plus`, from 0 up to `max`, read when the transition fires. Before, this took a generated document per item and a timer per nested element ([#124](https://github.com/seukwoo/nudg/issues/124)). TypeScript, Swift and Kotlin share the new conformance cases `delay-input`, `delay-input-max` and `validation-1.2`. Compiled programs are format 9 only when they use it, so runtimes from before 1.2 still read every other program. Schema 1.2; examples, motion libraries and presets declare 1.2.
- **Players on one element compose.** A shared press file on a card that also rises in used to lose one of the two motions, because each DOM player wrote the whole `transform` ([#122](https://github.com/seukwoo/nudg/issues/122)). Now they compose, as stacked modifiers already do on SwiftUI and Compose: transforms follow in bind order and opacities multiply. A size or color that two players write is reported once, and the last one bound keeps it. The element's own transform (inline, or from a stylesheet) stays outermost, so a badge centred with `translate(-50%, -50%)` or a rotated sticker presses in place instead of losing its placement ([#125](https://github.com/seukwoo/nudg/issues/125)). React Native gets `compose(...styles)` for the same thing. Also, `playDoc` on an element another player already marked with the same target name now binds it.
- **Reduced motion can change while a player runs.** Every runtime has `setReducedMotion(on, t)`: turning it on stops the loops it doesn't allow (they return to rest with the short tween, without a jump), turning it off starts the active states' loops, and motions from then on follow the setting. Every adapter now follows the system setting as it changes (DOM, React, React Native, SwiftUI, Compose), and a changed `reducedMotion` option applies to the running player instead of re-creating it, so a React Native player no longer jumps back to its first state when the setting is read. New conformance case `reduced-motion-live`. Reported from real use ([#121](https://github.com/seukwoo/nudg/issues/121)).
- **`destroy()` puts back the element's own inline styles.** The DOM adapter left its last `transform`, `opacity` and sizes on elements it let go of, so a host binding lazily couldn't tell them from its own, and an element with no player kept a transform (and the stacking context that comes with it). Unbinding now restores the inline values the element had before it was bound ([#121](https://github.com/seukwoo/nudg/issues/121)).
- **A sheet opened on mount shows its entrance.** The DOM adapter measured an element bound after the player started (every React ref) one frame later, so an event sent right after mounting (a bottom sheet opened in `useEffect`) moved toward an end computed from a size of 0, and the sheet appeared in place. An element is now measured as it is bound, and the measured values are applied before the first paint. The native adapters still measure after their first layout ([open question](docs/design.md#open-questions)). Reported from real use ([#120](https://github.com/seukwoo/nudg/issues/120)).
- **`playDoc` presses a button that holds another player's part.** `playDoc(doc, element)` bound the element to the file's first target only when nothing inside it carried `data-nudg`, so a settings row holding a switch's knob bound nothing and never moved. Now parts that name none of the file's targets don't count. Reported from real use ([#119](https://github.com/seukwoo/nudg/issues/119)).
- **compare measures sizes on the page it shows.** With `url` (the running app) or `html`, the sizes a file measures and `layout` doesn't give are measured on that page, as the DOM adapter would, so a sheet's verdict uses its real height instead of 0. The result says what was measured and in what window. `measureLayout` and `Measured` are exported from `@nudg/core/node`.
- **An example app: a messenger.** [examples/apps/messenger](examples/apps/messenger) puts the components together the way an app does: a chat list whose rows swipe to archive and close up, a stack transition into a chat, messages that rise in, swipe to reply and hold to react, a typing bubble, a composer whose microphone turns into send, and a jump-to-latest button. Voice and round video messages: hold to record, slide left to cancel, slide up to lock and tap to send, tap to switch between voice and video; a waveform that fills as a voice message plays, and a round video that grows and fills a ring around itself. It asks for the microphone and camera on the first press, records with them where the browser allows, and where it doesn't says why and records along a stand-in. Its README walks through how the code drives a file in three steps. Every motion is a nudg file, seven of them new and five reused unchanged from the examples; the app code holds no motion values. It's on the demo site.
- **A natural size follows its content.** A target measured by `naturalHeight` or `naturalWidth` (an accordion panel, a list row) wasn't measured again when its content grew, since nudg sizes its box; the DOM adapter now watches the children as well. It also measured overflow from children nudg was still moving, so a row whose content was rising into place stayed that much too tall; the transforms the player writes inside the element are now left out, as the spec says.
- **A drag taps nothing, in any player.** Releasing a drag swallowed the browser's click only for the player that dragged, so a target of another player nested inside it (a round video in a message you swipe to reply) still tapped. The DOM adapter now drops that click for every player.
- **A list of swipeable rows scrolls on touch screens.** The DOM adapter set `touch-action: none` on every target a file drags, so a finger on a row that swipes sideways couldn't scroll its list. A target the file drags along one axis now leaves the other to the page (`pan-y` for a sideways swipe). `dragAxes(program)` says which axis each dragged target uses, for other hosts. React Native, SwiftUI and Compose still take every touch on a dragged target; they follow next.

## 1.5.1

React Native keeps up with its own Animated, and agents show a change in fewer turns. Both came from measuring: a release build on an idle machine, and transcripts of agents editing the same bottom sheet. The format stays 1.1; the API only gains.

- **React Native keeps up with its own Animated.** The hook set every property on every frame, and React Native updates a view on each set, so a spinner (rotation, opacity, scale) cost three view updates a frame where React Native's JS-driven Animated costs one. Values that haven't changed are now skipped: in a release build with 60 spinners, nudg went from 13 to 25.5 JS frames a second, against Animated's 26.2.
- **Fewer turns for an agent to show a change.** Measured on the same four bottom-sheet edits, Claude with the skill went from 14.2 turns and $0.36 a change (1.4) to 11.0 and $0.25, all passing. The MCP instructions no longer tell the agent to validate after every edit (compare does it) or to read the whole guide before a small change; the skill says how an app's event reaches a file (`host.events` and `send`), and to pass the sizes a file measures.
- **compare says when a missing measurement can hide the change.** A file that measures a size (a sheet's height) and is compared without `layout` rests at 0 in both versions, so the change looked like none; compare and `nudg compare` now say which sizes to pass, first when the versions look identical.
- **A graph Chrome can't draw no longer fails the call.** `nudg_compare` and `nudg_plot` keep their verdict and numbers and say the picture is missing (headless Chrome can time out on a busy machine), and the error is Chrome's last line, not its display warnings.

## 1.0.0

The stable release. Format 1.0 freezes 0.18's semantics, and the public surface is pinned by tests on every platform: validator codes, the conformance suite, the schema, compiled programs, and the APIs of `@nudg/core`, the CLI, the MCP tools, the Swift package and the Kotlin modules. The native runtimes are checked on an iOS simulator and an Android emulator.

**Compatibility.** Within 1.x, files and APIs only gain: a 1.0 file means the same thing to every 1.x runtime, a code or API is never renamed, removed or given a new meaning, and new format features arrive as 1.x versions that a file opts into. Anything that would break waits for 2.0. Every 0.x file keeps working; `nudg upgrade` raises one to 1.0.

- **Format 1.0.** The stable format: 0.18's semantics under `"nudg": "1.0"`. Every 0.x file keeps working; `nudg upgrade <file...>` raises a file to 1.0 once it validates, keeping the rest of its text, and `--check` fails CI on older files. Schema 1.0. The examples, motion libraries and presets declare 1.0; the speed dial gained Escape to close, which the critique asks of overlays from 0.3 on.
- **Native, checked on devices.** The Swift package gained an XCTest suite (the conformance suite, a SwiftUI render checked pixel by pixel, the lifecycle) that runs on the Mac and, through `swift/test-ios.sh`, on an iOS simulator in CI. The Compose demo has instrumented tests that drive a tap, a drag and a two-finger pinch on an Android emulator. React Native's touch handling moved to a tested module.
- **Compose stops drawing when nothing moves.** The adapter requested a frame every vsync forever, which kept the app busy (and Compose tests from ever going idle). Frames now run only while something moves or a timer or long press is pending; time stands still while idle, so a motion started after a pause doesn't skip ahead.
- **One spec for 1.0.** [The format spec](docs/spec.md) is rewritten from eighteen "Additions in 0.x" sections into one document by topic (files, values, machines, events, inputs, motion, rest, compiled programs), with what each version added in an appendix.
- **A frozen surface.** [`docs/errors.md`](docs/errors.md) lists every validator, warning and critique code with what it means, and a test keeps it in step with the source. `api/` records the public API of every package entry point, the CLI, the MCP tools and the Swift and Kotlin modules; a test fails on any change until `npm run api` records it on purpose.
- **The 1.0 plan.** The roadmap's 1.0 stage covers the format, the frozen surface (error codes, conformance, schema, compiled programs, public APIs on every platform), one consolidated spec, native checks on an iOS simulator and an Android emulator, and a compatibility policy: within 1.x everything only gains.

## 0.13.0

Gestures and motion from input: long press and double tap, events when an input crosses a value or a scroll changes direction, and glide for flings without a snap point. Formats 0.14 to 0.16; hide-on-scroll, the free-scrolling carousel and a double-tap like have starters, and only two gaps remain in the catalog (animated list, pinch zoom).

- **Format 0.16: glide.** A state's `glide` lets a released value carry on with its velocity and slow down by itself, travelling velocity × `momentum`, the same projection `nearest` uses. At a range end (numbers or measured) it settles with the property's own spring. It rests when what's left of the travel is under 0.001. TypeScript, Swift and Kotlin share conformance; compiled programs are format 6. The free-scrolling carousel has a starter, checked with a real fling in Chrome; the decay gap is gone. Schema 0.16.
- **Format 0.15: events from inputs.** A crossing is an event key such as `host.volume>0.6` or `list.scroll.y<24`: it fires when an input sample crosses into the condition, once until it leaves. `target.scrolldown` / `scrollup` (and `scrollright` / `scrollleft`) report a scroll's direction, turning only after 8 units back from the furthest point. Inputs only, so every runtime agrees; TypeScript, Swift and Kotlin share conformance. Hide-on-scroll has a starter and the scroll-direction gap is gone. Schema 0.15.
- **Format 0.14: long press and double tap.** The runtime derives `target.longpress` (held 0.5 s; its tap is swallowed) and `target.doubletap` (a second tap within 0.3 s) from the down, up and tap every adapter already sends, only for targets the file uses them on. Deterministic and shared by TypeScript, Swift and Kotlin through conformance; a pending long press keeps the runtime from settling. The DOM adapter suppresses the context menu and touch callout on long-pressable targets. A double-tap-like example joins the reaction recipe. Schema 0.14.

## 0.12.0

Recipe coverage for common app patterns. Every UI word in the catalog now has a standard answer, and most have a validated starter: formats 0.10 to 0.13 add loops, measured map values, motion delays and a declared host, which give starters to spinners, skeletons, typing indicators, screen transitions, menus and speed dials. The catalog grew from 22 to 44 recipes and the site to 44 examples.

- **Recipes for what nudg can't do yet.** Menu, speed dial, animated list, spinner, skeleton, typing indicator, hide-on-scroll, stack navigation, full-screen modal, shared element, drawer, image viewer and free-scrolling carousel are in the catalog with `"starter": null` and the gaps the host fills. Gap capabilities are a fixed list, and `nudg recipe --gaps` counts them. Catalog version 2: `starter` may be null.
- **Nine new recipes with starters:** text field (floating label, focus line, error), checkbox, radio group, filter chips, star rating, badge count, page indicator, stepper and expanding search bar, each with an example on the site. A new "Fields & forms" category holds the field, search bar and stepper.
- **Format 0.10: loops.** A state's `loop` adds a periodic offset to a number while the state is active: `to` for a turn or a sweep, `keyframes` for a pulse, `delay` to stagger the same loop across dots, `wrap` so a spinner stops by the shortest turn. Values may be measured. Leaving hands the shown value and velocity to the next motion, reduced motion runs no loops, and a looping property counts as at rest for `onSettle`; `runtime.looping()` keeps adapters drawing. TypeScript, Swift and Kotlin share conformance; compiled programs are format 3. Schema 0.10.
- **Format 0.11: measured map values.** A numeric value in a map's `to` may be a measure object, resolved in the mapped property's coordinates; until layout arrives the map holds its compiled base. TypeScript, Swift and Kotlin share conformance; compiled programs are format 4. Schema 0.11.
