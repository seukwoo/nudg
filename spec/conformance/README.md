# Conformance suite

Language-neutral cases that define nudg's behavior. Any runtime that passes them is a nudg runtime.

Expected values are generated by [`derive.py`](derive.py), which is independent of every runtime: it integrates springs numerically (RK4, 10 µs steps) instead of using the closed form the spec prescribes. A runtime that passes agrees with the physics, not with another implementation. To change a case, edit `derive.py` and run `python3 spec/conformance/derive.py`; don't edit the JSON by hand.

## Behavior cases

```json
{
  "conformance": "0.1",
  "name": "What the case shows",
  "doc": { "nudg": "0.1", "...": "the file under test" },
  "files": { "motion/brand.nudg.json": { "...": "files it imports, by path relative to the doc" } },
  "steps": [
    { "t": 0, "expect": { "state": ["off"], "values": { "knob.x": 0 } } },
    { "t": 0.1, "send": "track.tap" },
    { "t": 0.2, "expect": { "values": { "knob.x": 12.581656 } } },
    { "t": 0.4, "send": "track.cancel", "handled": false }
  ]
}
```

- The doc is loaded as `main.nudg.json`; `files` resolve relative to it.
- Steps run in order. Times never decrease.
- `send` delivers an event at `t`. If `handled` is present, the runtime must report whether any state handled it.
- `expect.state` lists the active leaf states as paths (`checked/on`), in document order.
- `expect.values` lists some properties at `t`. Numbers match within 1e-6. Colors are hex and match within one step per 8-bit channel.
- `expect.resting` is whether every property is at rest at `t` (nothing moves, whatever timers are pending); `expect.settled` is whether, in addition, no unpaused timer is pending. The rule for rest is in the spec.

## Validation cases

A file with `documents` instead of `doc` lists documents and the exact set of errors each must produce, as `code` and JSON pointer `path`. Warnings are not compared. Error codes are part of the spec.
